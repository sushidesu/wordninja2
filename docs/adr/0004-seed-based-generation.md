# ADR 0004: 生成を種ベースに簡素化（QD 機構を退役）

- 日付: 2026-06-28
- ステータス: 採用
- 関連: ADR 0003（QD）の生成機構を置き換える。多様性を目的に置く精神は引き継ぐ。

## 背景・問い

ADR 0003 で生成を Quality-Diversity（exploit/explore モード、関係タイプのアーカイブ＝セル、PICK/ELITE、被覆ドリブン生成）として設計した。だが実運用で:
- hit-rate は QD 機構を足しても上がらなかった（採用率は数%〜十数%のまま）。良い結果が出た回も、効いていたのは「いいプロンプト＋多様な入力」であって、セル機構ではなかった。
- exploit/explore の手動オーケストレーション・elites 収集・被覆計算は複雑さだけが増えた。

問い: 生成フローをどう単純化すれば、多様で良いお題を楽に量産できるか。

## 決定

生成を「**種ベース**」に簡素化する。

- **シード語プール**: 辞書（wordfreq の高頻度日本語語）から作った一般語 約4000を `packages/topics/data/seed-words.txt` に置く。
- **生成**: 毎回プールから十数語をランダム抽出し、**各種語をペアの片側（1語目）に固定（アンカー）**して、LLM が「似ているが区別できる」相手（2語目）を創作する。種語ごとに1ペア。各ペアに自己評価（self 1-5 と relation）を付ける。
- **手本(few-shot)は固定せず毎回サンプルで回す**（固定の良い例が出力の mode を固定するため）。

  ※当初は種を「任意の発想のきっかけ（関連不要）」としたが、**任意だと種が出力を全く拘束せず無力化し、LLM がいつもの mode（鉄板ペア）に戻って“見たような組合せ”を繰り返した**（実測）。種の“引き”こそが多様性の源なので、片側固定（アンカー）に改めた。「辞書に引っ張られない」と「多様性」は両立しない。
- 以降は既存どおり: `/api/screen`（重複＋近すぎ排除）→ 人が /review → fold → 採用 → 関係タイプ付与。

退役（削除/不使用にする）:
- exploit/explore のモード分け
- QD アーカイブのセル（PICK＝手薄な型選択 / ELITE＝型ごとお手本収集）
- elites-few-shot、被覆ドリブン生成

## 根拠

- LLM 単独生成は typicality bias で出力が狭い型に偏る（mode collapse）。辞書からランダムに引いた語を発想の種にすると、初期状態に乱数が入り発想が散る。これは「多様性をアーカイブ被覆で制御する」より軽く、同等以上に多様性が出ると判断。
- 生成時点で per-pair 精度を上げようとするより、**多様性＝種のランダム性、品質＝生成＋自己評価＋screen＋人レビュー**、と役割分担する方が単純で速い。
- QD の「多様性を明示目的に置く」精神は、cockpit の関係タイプ被覆ビューで引き続き観測できる（生成を駆動する機構としては使わない）。

## 結果

- 生成フローが「種→自由生成＋自己評価→screen→人」に縮約。手動オーケストレーションが減る。
- 多様性は種プールのランダム性に依存する。プールの広さ・偏りが多様性に直結するので、プールはざっくり一般語で広く保つ（精緻なランク付けはしない）。
- 自己評価は甘い（生成物の機能アナロジー/比喩を高く付けがち）と実測済み。粗い signal として扱い、品質判定は screen＋人を主とする。
- ADR 0003 の生成機構は本 ADR で置き換え。評価・fold（ADR 0001/0002）と screen は不変。

## 留保
- シードに辞書を使うが、品詞や頻度の精緻な絞り込みはしない。プールの質より「広くランダム」を優先。
- ただし現プールは wordfreq 高頻度ゆえ**抽象語**（一切/状態/今後/深刻 等）も含み、抽象な種は抽象・近すぎペアを生みやすい（実測）。多様性は出るが質が落ちる場合があり、必要なら将来プールを具体名詞寄りに絞る余地がある（今は深追いしない）。
- avoid-list（既出を生成器に渡す）は今回採用しない。多様性はアンカーで担保する。
